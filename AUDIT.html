Portfolio Survey Docket

A full-stack audit of nine routes — correctness, navigation, accessibility, design system, performance, data integrity, and automation. Every claim below was verified against source, compiled CSS, or the running server.

The build is clean and the concept is genuinely distinctive. All nine routes prerender static, TypeScript passes with zero errors, and the orbital navigation is a real idea executed with care. Nothing here is a rescue job.

But three structural faults undercut it. The site has no link graph at all — the homepage ships zero <a> tags, so no crawler can reach eight of your nine pages and four of them have no way back to anywhere. The Tailwind config is silently ignored, so the brand cyan you designed around isn't the one that ships. And half the codebase is unreachable — 34 of 68 files, verified by import-graph traversal.

The good news is that the highest-impact fixes are small. A real <nav>, a sitemap.ts, one line in globals.css, and two JSON fields would resolve most of what's costing you visibility today.

01

Blockers

6 records · fix before anything else

These are ordered by damage done. The first two are cheap to fix and cost you the most.

B1BlockerSEO · A11y · UX

The site has no link graph. Eight of nine pages are unreachable by any crawler.

Navigation works by dispatching a window CustomEvent from a planet click, which PlanetTransitionOverlay.tsx:175 converts to router.push(). The destination URL exists only inside a JS event payload. Googlebot renders JS but does not synthesise clicks on arbitrary buttons.

curl localhost:3000/ → 0 <a> tags, 8 <button> /education /skills /work-experience /certificates → 0 anchors each next/link imported in 2 files site-wide · 3 router.push calls total no sitemap.ts · no robots.ts

Four pages are total dead ends — a visitor landing on /skills from anywhere has no route onward but the back button. No middle-click, no open-in-new-tab, nothing for a screen reader to enumerate, and no PageRank flowing anywhere.

FixAdd a persistent <nav> in layout.tsx with real <Link>s to all nine routes, plus sitemap.ts and robots.ts. Then make each planet a real <Link href={goto}> and keep the animation as an onClick decoration on top of it — the visual stays identical.

B2BlockerDesign

Your brand colour does not ship. tailwind.config.js is never loaded.

Tailwind v4.1.17 is installed via @tailwindcss/postcss, and globals.css opens with @import "tailwindcss" — but the config is v3-style module.exports and there is no @config or @theme directive anywhere. v4 does not auto-discover the file.

intended (tailwind.config.js) : cyan-400 #00e6ff · cyan-500 #00c2ff actually shipped (built CSS) : cyan-400 #00d2ef · cyan-500 #00b7d7 usages silently affected : 101 bg-hero-noise : emits nothing content glob ./src/components : directory does not exist

Meanwhile 11 hand-written #00e6ff literals do render the intended colour — so two different cyans ship side by side in the belief they are one.

FixDelete tailwind.config.js and move the tokens into a @theme{} block in globals.css. Leaving the file in place guarantees the next person repeats the mistake.

B3BlockerUX · Perf

Every navigation is blocked for 2.7–4.5 s, and up to 17.5 s in the worst case.

The transition overlay runs a fixed choreography before navigating — router.push fires only after MOVE_DUR + EXPAND_DUR + 120 = 1520 ms. It then waits for a page-rendered event to dismiss.

That event never fires again after first load. PageReadySignal lives in the root layout with a [] dependency array; the root layout never remounts across App Router navigations. So every hop falls through to blind timers instead: 3,000 ms typical, or MAX_WAIT_FOR_RENDERED = 16000 if /Rocket.json (116 KB, fetched cache:"no-store" every single time) fails to load.

click → 1520ms dead time → router.push → 1200–3000ms blurred scrim over an already-rendered page → total 2.7–4.5s per hop

FixCall router.push immediately and run the animation concurrently; dismiss on usePathname() change rather than the custom event; cap total overlay time near 600 ms. Add [pathname] to the PageReadySignal effect as a stopgap.

B4BlockerData

Two missing JSON fields silently blank out four features on /projects.

None of the six entries in src/data/projects.json sets featured or category. Both are optional in the Project type, and the JSON is cast with as unknown as Project[] — a double assertion that disables all checking. Nothing warns.

featured: 0 occurrences → pinned = [] → PinnedStrip returns null category: 0 occurrences → categories = [] → filter pills + dock render nothing → every card gets data-cat="" → scroll-spy observes nothing "Featured AI Projects" heading renders live, over an empty row

There is a second bug hiding underneath: the carousel's transform is x: (i - carouselIndex) * -336, which resolves to carouselIndex * 336 for every card — all featured cards would stack in one pile the moment featured is populated. The Next arrow also computes Math.min(pinned.length - 1, i + 1) = -1 on an empty array.

FixAdd featured and category to all six entries, change the transform to x: -carouselIndex * 336, and clamp the index at zero. Ten minutes of work restores four visible features.

B5BlockerAccessibility

prefers-reduced-motion is unhandled for every JavaScript animation on the site.

Two CSS media queries exist and both are inert — the one at globals.css:105 disables transition and animation on .orbit-planet, but the planets are positioned by inline left/top written from JS state, so they use neither.

Ungated and running continuously: the full-screen blur-and-zoom route transition (a textbook vestibular trigger, mandatory on every navigation), the orbit rAF loop on every page via SolarPreview, the 90–220-star canvas with mouse parallax, an infinite typewriter, a 2-second <h3> rotator, 3D book flips at rotateY:-180deg, and pointer-driven rotateZ parallax inside an open modal.

FixAdd the standard global CSS backstop, then a shared usePrefersReducedMotion() hook for the rAF and setInterval loops. Highest value single change: skip the transition overlay entirely and navigate immediately when the preference is set.

B6BlockerSEO

All nine pages are "use client", so per-page metadata is structurally impossible.

A Client Component cannot export metadata. Every route therefore inherits one title and one description from layout.tsx — verified byte-identical across all nine prerendered HTML files.

og: tags 0 twitter: tags 0 JSON-LD 0 rel=canonical 0 metadataBase absent sitemap absent public/social.png = 512×512 (needs 1200×630), wired to nothing favicon resolves at 29×32 · src/app/head.tsx is dead (absent from route manifest)

A recruiter searching your name gets one indexable page. Sharing any URL on LinkedIn produces a bare link with no card. Google has no machine-readable statement that this site is about a person named Kumar Shivraj Bhakat who is an AI/ML engineer.

FixSplit each route into a thin Server Component wrapper that exports metadata and renders the existing client component unchanged — roughly ten lines per route. Then add metadataBase, a real 1200×630 OG image, and Person + WebSite JSON-LD.

Automation

GitHub sync · CI · freshness

You asked specifically about pulling project updates from GitHub. Here is the recommended architecture, plus the CI that would have caught most of this report automatically.

A1Recommended

GitHub → projects.json via a scheduled Action that opens a PR.

Three options were considered. A scheduled Action that regenerates the JSON and commits it wins for your situation.

Action → commitServer Component + ISRClient fetch
Fits todaySite stays fully staticNeeds the repo's first server boundary—
Rate limitOnce daily, PAT = 5,000/hrVercel IPs are shared; unauthenticated = 60/hr → intermittent 403s60/hr per visitor, token exposed
ReviewableEvery change is a git diffInvisible until it rendersNo
Failure modeStale but correctGitHub outage → failed renderBlank cards, no SEO

Your content changes weekly at most. Paying a runtime dependency and a production secret for that is a bad trade, and a client fetch is disqualified outright.

Curation model Opt in by topic. Only repos tagged portfolio are pulled — you control the list from the GitHub UI with no code change.
Overrides always win. A committed projects.overrides.json keyed by repo name beats the API, so your hand-written prose (the five-step MindDocs architecture, for instance) is never overwritten.
Pinned → featured. Pinned repos come from the GraphQL API, which needs a PAT with read:user. This finally populates the field whose absence causes blocker B4.
Topics → category. Map llm|rag|langchain → "LLM / RAG", mlops|docker → "MLOps", and so on — fixing the other half of B4.

Pull name, description, topics, homepage, stargazers_count, language, pushed_at (a real last_updated instead of a hand-typed one), a README excerpt, and openGraphImageUrl as a cover fallback. Where a repo has no description, fall back to overrides → first README sentence → "${language} project", and push the repo name onto a warnings list the workflow turns into an issue.

Open a PR rather than pushing to main — it keeps a human deciding what the portfolio claims, at the cost of one click a week. Add a repository_dispatch trigger so other repos can ping this one on push for an immediate refresh.

A2High value

CI that would have caught most of this report.

There is no .github/ directory at all today. Three scripts do the heavy lifting:

  • check-assets.mjs — scan every "/foo.png"-shaped string in src/ and fail if public/foo.png is missing. This alone catches all 21 broken asset paths, and it must read .json as well as .tsx, which is exactly where an automated sweep went wrong earlier in this audit.
  • validate-content.mjs — zod schemas over the data files with .strict(), making featured and category required. That turns blocker B4 from a silent blank into a failed build, and .strict() catches typo'd fields like the detail:/short: mismatch.
  • tsc --noEmit + eslint . + next build — note that lint will fail on day one against 90 errors, so either land the cleanup first or start with continue-on-error and remove it once green.

Add Lighthouse CI with an accessibility budget, and grouped Dependabot (the three.js packages have tight peer ranges — ungrouped bumps produce PRs that each fail alone and pass together, though the better answer is to remove them entirely).

A3Recommended

A weekly freshness job, and one source of truth for the resume.

A Monday cron that opens or updates a single issue when it finds: a role listed as current for over 24 months, a role-based Microsoft cert past its 12-month window (matching AI-102, AZ-###, DP-### — and correctly not flagging Fundamentals certs like AI-900), a last_updated that disagrees with the repo's real pushed_at, and dead external credential URLs. On its first run it would flag the expired AI-102, the 11-month-stale /professional timeline, and the "current student" copy.

For the resume: a single src/data/resume.json in the JSON Resume schema, consumed by the three pages that currently each hardcode their own copy, and by a Playwright script that renders the PDF from the same template. One satisfies Exp[] on the mapping restores the excess-property checking that would have caught the detail: bug at compile time.

Analytics: none present. @vercel/analytics is cookieless and mounts in layout.tsx — one of the only Server Components you have. The signal worth having is which repo a recruiter actually opens.
